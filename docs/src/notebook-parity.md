# Notebook Parity

QMC.jl treats QMCPy as the reference standard for any notebook that declares an `Original QMCPy demo`. Shared notebooks should therefore be minimal Julia adaptations of the QMCPy example rather than independent rewrites.

This policy does not apply to Julia-native notebooks that do not cite a QMCPy source notebook.

## Maintainer Rule

If a shared notebook changes its seed, dimension, tolerance, sample budget, randomization choice, omitted sections, or section order in a mathematically meaningful way, the change must be documented both in the notebook header and in the tracking table below.

## Parameter Alignment Rules

| Parameter | Default rule | Allowed divergence |
| --- | --- | --- |
| Source notebook | Use the QMCPy notebook cited in the first Markdown cell as the reference document. | Only change the cited source when the QMCPy notebook was renamed or split; record both old and new paths in the PR notes. |
| Seed | Match the QMCPy seed exactly. | Change only for Julia-specific determinism or backend constraints, and record the old and new seed. |
| Dimension and discretization | Match the QMCPy problem dimension, time grid, and replication count. | Change only when the Julia package lacks the identical backend or when CI/runtime constraints make the original setup impractical; record the old and new values. |
| Tolerance and sample budget | Match the QMCPy stopping tolerance and sample cap. | Relax only for documented CI/runtime reasons or known algorithmic non-parity; record the old and new values and keep the original target in prose. |
| Narrative structure | Keep the same mathematical story and preserve shared section order. | Reorder only when Julia setup must come earlier for execution, or when unsupported Python-only sections are moved into a separate Julia notebook. |
| Optional dependencies | Keep the same conceptual example. | Julia may replace the dependency stack, but the notebook must say what was replaced and what mathematical behavior remains aligned. |
| Julia-only additions | Keep the shared core separate from QMC.jl extensions. | Additional Julia-only sections are allowed only after the shared core and must be labeled as extensions. |

## Target Parity Profiles

| Profile | Meaning |
| --- | --- |
| `Strict` | Match the QMCPy seed, dimension, tolerance, sample budget, and shared section order. Only API spelling should differ. |
| `Adapted` | Keep the same mathematical target and, by default, the same seed. Dimension, tolerance, or sample-budget changes are allowed only with an explicit notebook note. |
| `Split` | Keep the overlapping sections aligned with QMCPy, but move unsupported or out-of-scope Python sections into another Julia notebook or a prose note. |
| `Archival` | Preserve the cited source, figure-defining parameters, and mathematical story, but allow presentation-focused divergence for talk or paper artifacts. |

## Practical Use

When a shared notebook is edited, do not silently tweak seeds, dimensions, or tolerances to make the Julia notebook “look better” or “run faster.” Keep the QMCPy parameters unless there is a documented reason not to, and record any change in both the notebook and this page.
